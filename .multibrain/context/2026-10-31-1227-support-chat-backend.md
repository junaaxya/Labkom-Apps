# Support Chat Backend Handoff

- Added durable support-chat storage in `backend/prisma/schema.prisma` plus unapplied additive migration `backend/prisma/migrations/20261103000000_add_support_chat/migration.sql`, ordered after the current production migration chain.
- `POST /api/v1/support-chats` accepts strict `{ pcId, body }` only for `MAHASISWA`; it derives PC/lab and binds an immutable active `ASISTEN_LAB` duty from the matching lab and current or immediately prior Jakarta date. Prior date is necessary for an overnight shift that remains active after midnight. Candidates require `SCHEDULED`, active assistant account, active Shift, actual `evaluateShiftWindow()` interval, and deterministic `shift.startTime`, then schedule ID ordering.
- No PC maps to 404; no active duty maps to 409 with no chat/message/notification write. The transaction persists `WAITING` chat plus initial student message; `notifySupportChatAssigned()` runs after transaction success and uses `SUPPORT_CHAT_ASSIGNED`, targeted assistant ID, `/support-chats/:id`, and existing notification SSE delivery.
- List/detail/message routes admit only `MAHASISWA` and `ASISTEN_LAB`; service ownership is exact student or immutable assigned assistant. First assigned-assistant reply changes `WAITING` to `HANDLED`; student messages leave status unchanged.
- Original feature verification covered Prisma validate/generate, backend build, focused support/Jakarta guards, mounted HTTP route smoke, and strict-payload rejection. The selective integration preserves the latest dev schema, routes, API error contract, QR ticket flow, Academic navigation, and notification UI; the migration remains unapplied pending normal release review.
